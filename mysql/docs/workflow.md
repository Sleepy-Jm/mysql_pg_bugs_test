# 开发和实验流程

main 保存经过检查的基线。按任务建立 feat/version-8-0-xx 或 fix/oracle-报告号，完成一个明确改动即提交，经检查后合并。日期属于实验与日志，不作为必须每日创建分支的理由。

1. 收集官方报告与 Version 字段，保存 URL、抓取时间、原文哈希和锚点；保留缺正文/缺附件状态。
2. 建立报告 × 版本项，区分精确版本命中和历史推断。
3. 整理 SQL、cleanup/postcheck、oracle、环境、前提与局限。SQL 变更须重算哈希并重新验证。
4. 在独立环境回放目标版本，保存真实版本、构建、镜像摘要、会话设置、退出码、输出、执行 SQL 与分类依据。
5. 对目标异常，以相同 SQL/oracle 在严格相邻前版核对，检查环境可比性；8.0.32 对照 8.0.31。未知不能作无异常处理。
6. 原始大证据单独保存，Git 记录精简状态、哈希和位置；未复现和失败记录同样保留。

新实验先提交代码。复制 configs/run_manifest.template.json 到 local/<run_id>/manifest.json，填写 git rev-parse HEAD、git status --short、输入 SHA256、环境、命令和结果路径。结束后将脱敏 manifest/摘要提交到 experiments/<run_id>。只在工作区干净时以 commit 代表完整运行代码；否则保存改动 diff。

本次迁移没有重新运行数据库，历史代码提交无法确定时填写 unknown，不能追填本次整理 commit。模板对未来运行生效，旧记录按原始证据保留。

当前 runner 白名单冻结于 8.0.32–8.0.35，控制版本至 8.0.31。扩展新版本必须更新配置、runner 契约与测试，不得用新版本号覆盖旧实验。
