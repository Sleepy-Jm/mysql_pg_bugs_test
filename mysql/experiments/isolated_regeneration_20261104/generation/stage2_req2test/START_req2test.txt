2. 需求中的源码路径、URL 和行号只是来源标识，不授权你打开对应文件。
3. 完整示例用于学习 SQL 组织、数据设计、oracle 推导和证据表达；示例答案不是当前任务答案。
4. 不根据目标 SHA、函数名或既有记忆搜索和补全已知复现步骤。
5. 需求缺少关键语义或可执行前提时，将对应候选标记 blocked，列出需要分析阶段补充的问题，不自行查源码或猜造开关。补充需求须经协调者另建 attempt 交接，不覆盖当前输入。
6. 若从允许材料中发现与示例目标存在相关修复或实质相同的触发机制，记录重合并停止独立评测尝试；不要为调查重合而查阅禁读材料。
7. 需求若夹带原始源码块、当前目标历史 SQL/运行答案，或误读白名单外材料，记录暴露内容和时点，停止清洁尝试，不默默删除后继续。

【执行顺序：先完整示例，再当前任务】
第一步：核验输入后，完整读取 complete_example，包括需求和完整测试答案。
第二步：读取并核对交接清单及当前 requirements.txt。
第三步：按本次需求生成测试，不改写需求以适配自己的 SQL。

【测试生成要求】
Prerequisites
- 写明版本/语法前提、会话设置、连接数和执行顺序。
- 使用已选择的可丢弃 schema；对象名称保持独立。
- 保存并在正常结束时恢复修改的会话设置。

SQL
- 给出完整 setup、INSERT、查询、必要的 PREPARE/重复执行、对照和 cleanup。
- 不省略会话或状态依赖，不用占位 SQL。
- 采用小型、可手工核算的数据和确定性输出顺序。
- 每个检查点具有唯一 case_id，并映射到需求中的 C/R 编号。
- 仅清理本测试创建的对象。

Expected results and oracle
- 逐项推导每个 case_id 的预期结果。
- 正确处理重复行、NULL、排序、字符集和数值精度；涉及哪些就说明哪些。
- 近似数值需声明容差及理由。
- 从输入数据和 SQL 语义推导结果，不把父提交输出或另一条共享实现的查询当作唯一 oracle。
- 不填写“目标版本预计返回的错误值”。

Coverage observation
- 将源码覆盖观察计划与结果正确性检查分开。
- 只能依据需求转述观察计划；明确本阶段未确认实际分支可达。
- 不声称 SQL 语法合法就意味着命中了目标路径。

Execution status
- database_executed=false
- coverage_status=not_measured
- reproduction_status=unknown
- 如有静态检查，单独记录；不得将其称为数据库实测。

【保存与冻结】
在本次输出目录保存：
- test.sql：完整可执行脚本。
- expected.json：按 case_id 保存列名、预期行、顺序要求及适用容差，SQL NULL 用 JSON null。
- oracle.md：独立计算过程。
- requirement_mapping.json：case_id → C/R 编号及主候选/对照角色；另列 blocked 候选及原因。
- stage2_response.txt：完整最终阶段回答。
- generation_manifest.json：实验/run/attempt/目标身份、实际输入与输出路径及可计算的 SHA256、启动提示词哈希、已知生成配置/环境、实际命令、额外上下文、越界情况和未执行状态。

允许在本次输出目录编写并运行只使用标准库的纯算术程序核算 oracle；不得调用数据库、下载依赖或读取其他实验资料。保留程序、命令与计算来源。解释器运行不等于许可扫描其安装目录。
未知的模型配置等字段写 unknown，不虚构信息。缺输入哈希则按启动规则阻塞，不用 unknown 绕过。
完整消息和工具日志由协调者保存；stage2_response.txt 不冒充完整对话日志。
blocked 候选也必须保存原因，不能只保留可生成的成功候选；全部 blocked 时不伪造 test.sql 或 expected.json。
清单不包含自身哈希，协调者在最终冻结清单中记录它。生成后停止修改本次输出；后续执行反馈和修正另记 attempt_id。
不要修改原始输入、覆盖旧 attempt、提交仓库、连接数据库或宣称已复现异常。
