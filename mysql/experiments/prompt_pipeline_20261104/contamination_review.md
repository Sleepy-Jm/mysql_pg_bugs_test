# 提示词与 SQL 生成的答案污染审查

审查日期：2026-11-04。范围为本批三个目标的输入包、实际阶段文件、生成脚本、同一对话中生成前的文件读取记录，以及后续实测证据。本审查没有重新生成 SQL、运行数据库或修改历史输入输出。

**结论：这次不能认定为无污染盲测。** 两阶段由同一助手在共享上下文中直接完成；窗口 AVG 案例在生成前已经接触另一版本的相关分母实现，属于已确认的答案相关上下文暴露。此外，目标选择和源码节选已有很强的定位引导，输入包还包含人工种子需求。现有记录没有显示本批运行后的错误结果被反灌进原 SQL 或预期值。三个案例的真实复现仍成立，但不支持未知缺陷独立发现率、严格隔离的两阶段模型效果或“完全无答案污染”的主张。

## 1. 这里的“污染”具体指什么

如果实验旨在检验“只看当前目标允许的源码，独立提取条件并生成测试”，同一目标的修复、已知触发 SQL、预填的需求答案、先前的运行错误或同对话中相关解题信息，都可能越过预定信息边界。仅在文件层面把 src2req 与 req2test 分目录，不能保证模型的信息隔离。

源码中可直接读出的条件、允许使用的异目标完整示例，以及由数据和 SQL 语义推导的预期值，本身不等于泄漏。关键是它们是否属于事先定义的输入，是否包含当前目标的答案，以及结论是否与实际信息条件一致。本批应定位为“已选目标的源码引导、非盲复现开发案例”。

## 4. 按生成阶段和案例判定

| 范围 | 已确认 | 未能确认/应避免的说法 |
|---|---|---|
| src2req，字符集和 Item | 精确已选目标及强定位源码输入；同一对话中完成 | 未确认当前目标已知触发 SQL 被直接读取；不能把“不见直接读取”写成“完全无污染” |
| src2req，窗口 | 上述引导，另有同对话的 AVG 分母相关实现暴露，输出也提到另一个示例实现 | 不能声称只根据这次局部源码独立发现；不能量化暴露造成的收益 |
| req2test，全部 | 正式需求由本次 src2req 填入，但作者仍保留前阶段的源码和对话信息 | 不能声称测试生成器只见需求、完全不知道源码或其他先验 |
| SQL/oracle，全部 | 归档顺序是先生成，再实测；执行时 SQL/预期哈希可与归档核对 | 未发现本批运行后调答案的证据；不能排除既有知识或模型训练记忆，且当前记录不能量化它们 |
| 后验源码机制文档 | [source_mechanisms.md](source_mechanisms.md) 在运行后补读源码并解释异常 | 是结果解释材料，不是生成时输入；若以后给模型看，再测试同一机制就是已暴露目标 |

从文件和公开动作记录能判断输入边界与时间关系，不能还原模型内部因果过程。这里没有做记忆污染测量，也没有与清洁上下文的对照生成。

## 5. 仍然有效与不成立的实验结论

仍然有效：归档 SQL 在六个精确源码版本上真实执行；三组父提交均满足预期，目标提交分别有 1、2、5 个稳定错误检查点，每个版本三轮。预期值来自明确数据的语义推导，父提交的输出是交叉核对而非定义正确性的唯一依据。保存的 XML、哈希和离线比较可复核这些行为事实。

不成立：将三组成功等同于“100% 未知 bug 发现率”，宣称独立新缺陷发现、无答案污染、两阶段隔离收益，或认为每个失败检查点对应一个独立根因。成功案例的筛选和展示也不构成未筛选目标集的效果评估。内部源码路径仍没有插桩覆盖证据。

因此将它们整理为 [开发参考样例](../../examples/mysql/source_guided_reproductions/README.md)，明确标记 `evaluation_eligible=false`。这是用途限制，不是否定其复现证据。

## 6. 后续实验如何得到更可信的独立结果

1. 先固定问题定义和输入边界。若研究源码引导，说明目标如何选出、允许的节选如何产生；不要把人工已定位根因的贡献算成模型自动定位。
2. 把已知成功样例放入开发集合，按相关修复、父子提交与语义相同的触发机制分组，避免进入留出评测。不要只按 SQL 文本哈希去重。
3. 使用新上下文分离两个阶段。src2req 只接收约定源码和开发示例；req2test 只接收开发示例与本次实际需求。当前目标的种子需求、修复、回归 SQL、旧报告和历史回答不得进入这次输入或检索范围。
4. 保存实际发送的完整消息、系统/阶段指令、模型配置、可访问文件/检索清单、每次响应及其哈希；在执行前冻结 SQL 与 oracle。新聊天可消除显式对话延续，但不能证明预训练中完全无相关内容。
5. 运行结果揭晓后才补读修复和报告进行解释。保留所有首次尝试，包括无效 SQL、正确结果和不可达候选；按事先约定的目标集计算指标。带执行反馈的迭代单独统计。

现有归档不会被改写成符合这些新要求的历史记录。未来清洁实验另建 run_id 并保留本次开发样例的暴露清单，才能清楚区分“样例帮助下的开发成功”和“留出目标上的独立能力”。
