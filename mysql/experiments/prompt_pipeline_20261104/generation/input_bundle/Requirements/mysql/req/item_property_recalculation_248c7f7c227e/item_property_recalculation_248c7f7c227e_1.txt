Candidate construction
Family A: reuse of an expression containing a window function.
- Use a small InnoDB table with a unique ordering key, a partition key and exact numeric values. Put a window function inside an arithmetic or comparison expression in the SELECT list, instead of testing only a bare window function. Choose explicit partitions, deterministic ordering and a buffered frame where appropriate.
- Prepare the statement once and execute it at least three times in the same connection without re-preparing, changing data or reconnecting. Provide a separate stored-procedure variant that creates the procedure once and calls it repeatedly, since the reuse paths need not be identical. Include correct client delimiter handling for procedure creation.
- Compare each execution with a direct-query control and a hand-derived expected table. Keep the initial and later executions separately labeled; do not claim that every prepared window query reaches the relevant refresh.

Family B: window-bearing left operand of IN.
- Place a legal window expression in the SELECT list as the left operand of IN (SELECT ...), using a correlated inner query where useful to preserve an Item_in_optimizer path. Wrap the predicate in CASE and include another window expression to exercise window materialization.
- Use explicit ROWS frames and unique ordering keys. Do not place a window function in WHERE or nest window functions. Keep correlated names qualified and ensure scalar/row arity matches.
- Begin with non-NULL, small data and membership outcomes that can be enumerated. One useful invariant is CASE WHEN predicate THEN a non-NULL payload column ELSE the same payload column END: the result must equal that payload whether the predicate is true, false or unknown. Include a companion CASE with distinguishable branches and known membership so the test also detects branch-selection errors.
- Add a plain-column left operand control, a window-expression-without-IN control, then NULL and empty-inner-result variants separately. These controls do not guarantee that the optimizer chooses the same internal representation.
