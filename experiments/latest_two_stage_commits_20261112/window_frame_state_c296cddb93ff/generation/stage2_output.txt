1. Construction realization

Stage 1 supplies one evidence-backed candidate (C1) and one explicitly unresolved construction hypothesis (H2). The mapping below keeps those separate.

C1 (supported by the handoff): `AVG(X) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN k PRECEDING AND CURRENT ROW)` binds the sensitive operand `X` to the `Item_sum_avg` argument; the same `Window` object is shared with `param->m_window`. The optimized ROWS branch is entered when `optimizable_row_aggregates()` and `aggregates_primed()` are true and the frame is not `UNBOUNDED PRECEDING AND CURRENT ROW` (so `needs_buffering()` is true). The sensitive state is `rowno_in_frame` set to `current_row - lower_limit + 1` while the actual frame is `[lower_limit, upper]` with `upper > current_row`. To exercise that, the frame must contain rows after the current row while the frame end has stopped advancing (partition/cache end reached). The SQL-visible oracle is the arithmetic mean of the non-NULL `X` values over exactly the frame rows; the target's divisor is smaller than the frame size, so the returned AVG is too large in magnitude when the frame sum is nonzero. The remaining unresolved link is the exact `copy_funcs` dispatch to `Item_sum_avg::val_*`; the handoff cites the comment at `window_iterators.cc`:1154 tying the branch to final AVG division, but the dispatch itself is not excerpted. Tests T1–T4 are exploratory C1 candidates that vary the frame geometry and the position of the current row relative to the frame end; they are not five independent confirmations of C1, and none is claimed to be a satisfied requirement.

H2 (construction hypothesis, not satisfied): the handoff states no supplied path demonstrates `optimizable_row_aggregates()` true with a stale `first_rowno_in_rows_frame` or `rowno_being_visited`. T5 is therefore an exploratory MIN/MAX probe that only checks whether the optimized ROWS block preserves the invariants on a frame where the first row is brought back into the frame; it cannot confirm H2 without the missing caller/guard evidence. If T5 returns the true extremum, that is consistent with the invariants holding on this path and does not establish H2.

2. SQL

```sql
-- T1: C1 exploratory. Frame [i-2, i+2] with partition end reached so upper > current_row.
-- Sensitive operand is x in AVG(x); rows after current row are in the frame.
CREATE TEMPORARY TABLE t1 (p INT NOT NULL, o INT NOT NULL, x INT NOT NULL);
INSERT INTO t1 VALUES
 (1,1,10),(1,2,20),(1,3,30),(1,4,40),(1,5,50),(1,6,60);
-- Target query: current row o=3, frame rows o=1..5, true mean = 30.
SELECT o, AVG(x) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING) AS a
FROM t1 ORDER BY o;
-- Contrast: same frame but current row is the last row (upper == current_row), no trailing rows.
SELECT o, AVG(x) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN 4 PRECEDING AND CURRENT ROW) AS a
FROM t1 ORDER BY o;
DROP TEMPORARY TABLE t1;
```

```sql
-- T4: C1 exploratory. Two partitions; only the first partition reaches the cache end
-- with trailing frame rows, the second does not. Isolates the "upper > current_row"
-- condition from partition-boundary effects.
CREATE TEMPORARY TABLE t4 (p INT NOT NULL, o INT NOT NULL, x INT NOT NULL);
INSERT INTO t4 VALUES

-- Contrast: frame ending at current row in both partitions.
SELECT p, o, AVG(x) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS a
FROM t4 ORDER BY p, o;
DROP TEMPORARY TABLE t4;
```

```sql
-- T5: H2 exploratory only. MIN/MAX over an optimized ROWS frame where the first row
-- is brought back into the frame; checks whether first_rowno_in_rows_frame and
-- rowno_being_visited stay consistent. Does not confirm H2 without the missing guard.
CREATE TEMPORARY TABLE t5 (p INT NOT NULL, o INT NOT NULL, x INT NOT NULL);
INSERT INTO t5 VALUES
 (1,1,9),(1,2,3),(1,3,7),(1,4,1),(1,5,8),(1,6,2);
SELECT o,
       MIN(x) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN 2 PRECEDING AND 1 FOLLOWING) AS mn,
       MAX(x) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN 2 PRECEDING AND 1 FOLLOWING) AS mx
FROM t5 ORDER BY o;
-- Contrast: same frame, but with a strictly increasing sequence so a stale cache
-- would be visible as a wrong extremum.
SELECT o,
       MIN(x) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN 2 PRECEDING AND 1 FOLLOWING) AS mn,
       MAX(x) OVER (PARTITION BY p ORDER BY o ROWS BETWEEN 2 PRECEDING AND 1 FOLLOWING) AS mx
FROM (SELECT p,o,o*10 AS x FROM t5) s ORDER BY o;
DROP TEMPORARY TABLE t5;
```

3. Expected results and path observations

T1: target query returns six rows; for o=3 the frame is o=1..5 with values 10,20,30,40,50, true mean 30. The target's divisor is `current_row - lower_limit + 1 = 3 - 1 + 1 = 3` (minus null count 0), so the target predicts 150/3 = 50 for o=3, not 30. Contrast (frame ending at current row) has `upper == current_row`, so the sensitive assignment does not apply and the mean should equal the arithmetic mean. Observation needed: confirm the same `Window` reaches `param->m_window`, that `row_optimizable` and `aggregates_primed()` are true, and that `copy_funcs(CFT_WF_FRAMING)` is called with `rowno_in_frame = 3` while the frame is `[1,5]`. The dispatch from `copy_funcs` to `Item_sum_avg::val_*` is the unresolved link; without it, a matching output is not evidence of the intended object mapping.

T2: for o=3 the frame is o=2..6, values 11,13,17,19,23, true mean 83/5 = 16.6. Target divisor `3 - 2 + 1 = 2`, predicting 83/2 = 41.5. Contrast frame ending at current row should match the arithmetic mean. Same observation requirements as T1; the asymmetric frame changes the gap `upper - current_row` from 2 to 3, which is a different magnitude of the same mechanism, not a different mechanism.

T3: for o=3 the frame is o=1..5 with non-NULL 4,6,8,10, true mean 7. Target divisor `3 - 1 + 1 = 3` minus null count 1 = 2, predicting 28/2 = 14. Contrast replaces NULL with 0, so the frame sum is 28 and the divisor is 3, predicting 28/3 ≈ 9.33; this isolates the null-count subtraction from the position-vs-size difference. Observation needed: confirm `m_frame_null_count` is 1 on the target call and that `rowno_in_frame` is 3 rather than 5.

T4: partition 1, o=3, frame o=2..4, values 200,300,400, true mean 300; target divisor `3 - 2 + 1 = 2`, predicting 900/2 = 450. Partition 2, o=2, frame o=1..3, values 1,2,3, true mean 2; target divisor `2 - 1 + 1 = 2`, predicting 6/2 = 3. The contrast frame ending at current row should match the arithmetic mean in both partitions. Observation needed: confirm the cache-end condition (`upper > current_row`) is what selects the sensitive assignment, not the partition boundary itself.

T5: for o=3, frame o=1..4, values 9,3,7,1, true MIN 1 and MAX 9; for o=4, frame o=2..5, values 3,7,1,8, true MIN 1 and MAX 8. The contrast with `x = o*10` gives strictly increasing values so a stale cache would show as a wrong extremum. Observation needed: confirm `optimizable_row_aggregates()` is true, that `bring_back_frame_row` sets `rowno_being_visited` to the fetched row, and that `first_rowno_in_rows_frame` equals the actual frame start at each `compute` call. If the invariants hold on this path, T5 is consistent with the handoff's statement that no supplied path breaks them; it does not confirm H2, and the missing caller/guard evidence remains outstanding. No execution or instrumentation is claimed for any of T1–T5.
