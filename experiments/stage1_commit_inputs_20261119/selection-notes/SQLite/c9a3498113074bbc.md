## 如何在不知道报告时选上下文

先读原提交说明和新增判断。在此版本的 src/ 核心源码中执行下面三项查找，再依固定规则摘取。每行均可从原始材料独立得到。摘录均保留原文，未给模型添加哪条路径最可能出错的提示。

| 问题 | 从何处得到检索词 | 命中后选什么、何时停止 |
|---|---|---|
| 谁调用改变决策的函数？ | 主补丁显示 sqlite3CodeRhsOfIN 改变了是否复用的判断。按函数名检索直接调用，剔除声明、定义、注释。 | 收入全部两个实际调用点及保护该调用的局部分支。一个在 sqlite3FindInIndex，另一个在虚表路径 sqlite3WhereCodeOneLoopStart。无需预判哪个入口会进入最终样例。到直接调用者即止。 |
| 新的相等判断比较了什么，比较值从哪里来？ | findCompatibleInRhsSubrtn 有两次排除不匹配的比较，操作数分别为 selId 和 zAff。沿 pSig 初始化的右值追一层。 | zAff 来自 exprINAffinity，收入其函数体。selId 来自 Select.selId，按字段写入检索，区分接收对象类型，纳入 4 处 Select 的直接赋值：创建、复制、复合子查询展平、视图展开时重新编号。赋给 SubrtnSig 或 AggInfo 的同名字段属于值的消费，其中签名赋值已在补丁中。此处停在产生比较值的一层，未继续展开通用类型转换和字节码 API。 |
| 原说明点名的查询转换究竟在何处发生？ | 原文直接出现 predicate push-down。用这个词在核心源码中找到 pushDownWhereTerms，再查它自身及其直接调用点。 | 收入原注释中的查询改写示意、实际复制及放置谓词的分支、sqlite3Select 中调用该转换的开关条件。自递归调用不另展开。此处不遍历其他查询重写。 |

例如，单凭函数名就能看到虚表入口。即使尚无证据说明最终查询使用了虚表，它仍与普通入口采用相同的纳入规则。对 selId 也做同样处理，把保留编号和重新编号的路径都纳入。这样模型能够自己提出相反的假设。摘录仅补充局部入口和数据来源，具体 SQL 会选择哪条计划仍须独立验证。

## 复核和输入来源

~~~sh
rg -n 'sqlite3CodeRhsOfIN\(' src
rg -n 'p(NewSig|Sig)->(selId|zAff)|exprINAffinity\(' src
rg -n --pcre2 -- '->selId\s*=(?!=)' src
rg -n -i 'predicate push-down|pushDownWhereTerms\(' src
~~~
