# 两阶段：修改路径与异常触发

基于 `two_stage_compact_source_20261112` 创建。原版和历史证据未修改。

## 使用

1. 将 `stage1_construction_prompt.txt` 全文作为 Stage1 输入。
2. 将本次实际 Stage1 输出替换到 `stage2_sql_prompt_template.txt` 唯一的 `{{STAGE1_OUTPUT}}`，再作为 Stage2 输入。

本包不改变 API 模型或参数，没有调用模型或执行 SQL。

## Stage1：替换分析结构，不叠加规则

旧的三个输出部分替换为两个连续目标：

1. 如何进入修改路径：SQL 位置、对象来源、调用与分支条件、配置和操作顺序，以及应观察的对象与分支。
2. 到达后哪些敏感输入可能触发异常：固定同一对象和输入，比较父子版本操作，形成“SQL 构造 → 目标对象/路径 → 敏感属性 → 操作差异 → 可能的语义破坏 → 可观察结果和独立正确预期”的候选关系。

第二部分本身就是交给 Stage2 的构造依据，不再另写一遍优先要求清单。未建立的环节保留在候选中，不升级为必要条件。父子差异和路径命中不自动等于 bug。

无关聚合示范同步改成两个部分，其合成源码未变。示范明确区分目标候选、路径对照和数据表面变体，没有加入当前案例的触发答案。

## Stage2：五条 SQL 的差异依据

只替换原“五条差异化测试”段落。T1-T5 分别关联 Stage1 的候选编号，说明其考察的不同分支/操作数关系、敏感机制，或预期影响不同的输入边界。可以共享有依据的路径条件，但不能围绕同一个未经证实的前提换五种表面写法。不足五个有依据的候选关系时，说明缺口，不编造补足。敏感输入、SQL、独立预期和路径观察的其余要求、无关示范及目标元数据保持不变。

## 保持不变的材料

当前案例源码正文、三段对象来源源码、生产 diff、commit message、注释和来源记录均与精简版逐字节一致，没有新增源码。`stage1_changes.patch` 和 `stage2_changes.patch` 可审阅改动。

Stage1：32,941 字节（原 33,335）；Stage2：5,472 字节（原 5,360）。这些修改明确任务与候选依据，不构成模型不会推导出错的保证。
