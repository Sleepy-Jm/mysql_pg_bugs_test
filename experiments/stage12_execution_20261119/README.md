# DeepSeek 原始 SQL 的直接命中实验

在预先选定的 12 个独立查询结果缺陷中，60 份原始 SQL 直接命中 **1/12（8.3%）**。SQLite 的 T2 复现视图计数错误。PostgreSQL 的 T4 另复现一项上游已知回归，单列为样本外发现。fuzzing 新增命中尚未测量。

| 数据库 | 原始 SQL | 预设目标 | 直接命中 | 主实验执行次数 | 额外归因验证次数 |
|---|---:|---:|---:|---:|---:|
| [MySQL](MySQL/README.md) | 20 | 4 | 0 | 240 | 0 |
| [PostgreSQL](PG/README.md) | 20 | 4 | 0 | 240 | 6 |
| [SQLite](SQLite/README.md) | 20 | 4 | 1 | 240 | 60 |
| 合计 | **60** | **12** | **1** | **720** | **66** |

主实验 720 次中，603 次脚本全部语句完成，117 次含 SQL 错误。归因验证也执行了 66 次，总计 786 次。报错次数按脚本运行统计，包含输入本身不合法和按脚本设计预期出现的错误。缺陷数单独按归因统计。

生成批次 [run_20261119_124816](../stage12_generation_20261119/run_20261119_124816/README.md) 有 60 份冻结 SQL，覆盖 MySQL、PostgreSQL 和 SQLite 各 4 个预先选定的查询结果缺陷。每个目标对应 T1 至 T5。主比较的四个版本为引入提交及其第一父版本、修复提交及其第一父版本。每份原始 SQL 在每个版本独立执行三次。各数据库的版本表和原始输出见 [MySQL](MySQL/plan.json)、[PostgreSQL](PG/versions.csv) 和 [SQLite](SQLite/plan.json)。

## 判定口径

命中单位是预先登记的独立缺陷。对同一份冻结 SQL，检查缺陷版本能否重复产生上游描述的错误结果、依据输入数据或等价查询算出的正确结果，以及修复能否消除错误。引入前后的变化用来补强归因。语法当时尚未实现、编译期开关、原脚本自身的 SQL 错误、无序返回和随机表达式均按实际表现记录。同一根因的重复报告、同一目标的多次重复执行都只计一次。

脚本按原字节执行。MySQL 客户端和 SQLite 执行器都在首次 SQL 错误后停止该脚本。PostgreSQL 客户端可以在语句报错后继续，因此含错误的脚本仍可能保留后续对照查询的结果。此处测量直接命中，fuzzing 新增命中待后续实验测量。

## MySQL 的逐目标结果

| 目标 | 原始 SQL 的实际表现 |
|---|---|
| #103331，NOT IN 缓存丢失 NULL 状态 | T1、T3 向主键插入 NULL，四个版本均在准备数据时报错。其余三份结果在两条边界均相同。 |
| Oracle #33603911，带警告的临时表聚合漏行 | 五份均执行完成，修复前后结果一致。 |
| Oracle #32193123，聚合列计算顺序错误 | T1、T2 均被默认的 ONLY_FULL_GROUP_BY 拒绝。其余三份的结果在两条边界均相同。 |
| #118033，DECIMAL 谓词的常量替换 | T2 的除法写入 DOUBLE 在引入点改变舍入结果，修复前后相同。原始 SQL 没有比较 DECIMAL 列与更多小数位的常量。 |

MySQL 共 192 次脚本完成、48 次因上述两种 SQL 错误停止。复核记录包含每轮结果、稳定性，以及各份 SQL 采用的完整值、指定列或数值容差核验。[MySQL 统计](MySQL/verification.json) · [独立预期](MySQL/oracle-notes.md)

## PostgreSQL 与 SQLite 的逐目标结果

| 数据库与目标 | 原始 SQL 的实际表现 |
|---|---|
| PostgreSQL #17335，并行 Append 重复行 | 两条边界上结果均符合预期，首次采集的执行计划均未采用并行 Append。 |
| PostgreSQL #18522 / #18526，归并右反连接 | 五份脚本使用哈希反连接或子计划。修复前后的目标查询均返回预期数据。 |
| PostgreSQL #19533，窗口 COUNT 遇 EXCLUDE 漏行 | 五份均未使用 EXCLUDE。T4 触发下述另一项已知错误。 |
| PostgreSQL #18771 / #19425，ICU 比较强度 | T1、T3 的排序未区分错误和正确的比较强度。部分语句因版本不支持语法或历史目录列名而报错。 |
| SQLite 视图计数忽略 DISTINCT | **T2 命中。** 修复前目标返回 7、等价对照返回 5。修复后两者均返回 5，各三轮一致。原始引入提交默认关闭该优化，显式开启后，在同配置的引入边界复现 5 → 7。 |
| SQLite 多列 IN 漏行 | 四份确定性脚本在修复前后相同。T2 使用 random()，在同一版本上重复执行也会变化。 |
| SQLite UNION ALL 行数限制 | T2、T4 在引入边界有变化，在目标修复前后相同。 |
| SQLite 十进制转浮点 | 引入边界的两份输出有格式化尾数变化。目标修复前后五份结果相同，均未出现数值翻倍。 |

PostgreSQL 的窗口 T4 还命中一项样本外的已知回归。五行数据执行全窗计数并按计数等于 5 过滤，应返回五行。修复 `53823a06be6f` 的父版本连续三次拒绝目标查询并报告 `function with OID 0 does not exist`，同一脚本里的物化对照每次都返回五行。修复后三轮的目标和对照均返回五行。这 1 项单列于 12 个目标之外。[PostgreSQL 运行记录](PG/README.md) · [六次额外执行](PG/secondary_check.json) · [上游修复](https://github.com/postgres/postgres/commit/53823a06be6f40d88d8e3ba45045ecee1a21fc5e)

SQLite 额外执行了视图计数优化的历史默认启用边界，以及原始引入边界上两侧均显式开启优化的配置。这 60 次附加执行使用相同的 T1 至 T5。[SQLite 版本与配置](SQLite/README.md) · [逐脚本比较](SQLite/summary.json)

## 公开归档

MySQL 的 16 份版本回执在 `server_version` 中保留程序名和版本，省去了服务器专用目录。运行 SQL、实际提交号、原始查询输出及其校验值均保留。PostgreSQL 归档含逐轮回执及 82 份首次执行的查询计划日志。种子对照实验的准备状态见 [SQLRight 环境核验](../sqlright_environment_20261119/README.md)。
